# HMM Market Regime Detector

A Streamlit dashboard that uses a 3-state Hidden Markov Model to classify every
trading day in SPY's history as one of three market regimes: **Calm**, **Choppy**,
or **Stress**.

> **Important caveat up front**: these states are *volatility-and-stress regimes*,
> not directional bull/bear signals. The model tells you *what kind of market
> environment* you are in — not whether prices will go up or down.

---

## Quick start

```bash
# 1. Clone and install dependencies
git clone https://github.com/your-org/hmm-regime-detector.git
cd hmm-regime-detector
pip install -r requirements.txt

# 2. Add your FRED API key (free at https://fred.stlouisfed.org/docs/api/api_key.html)
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
# edit .streamlit/secrets.toml and paste your key

# 3. Build the historical data cache (run once; takes ~60 seconds)
python scripts/build_cache.py

# 4. Fit and pickle the HMM (run once; takes ~30 seconds)
python scripts/fit_model.py

# 5. Launch the app
streamlit run app.py
```

## Architecture

### Hybrid data layer

The app keeps a pre-built CSV (`data/historical_cache.csv`) covering
2000-01-01 through the last time `build_cache.py` was run.  On each session
load it checks whether the cache is stale; if today's date is past the cache's
max date, it fetches only the *incremental* difference from yfinance and FRED,
then concatenates.

This means:

- **Cold start is fast** — reading a CSV is instant vs. re-downloading 25 years
  of data on every page load.
- **Live data is fresh** — new trading days appear within the hourly cache-TTL
  window set on `load_data_cached`.
- **FRED series** (HY OAS, yield curve, NFCI) update weekly or monthly; the
  loader forward-fills the last known value and notes the staleness.

### Walk-forward validation

The model is fit **only** on 2007-01-01 through 2018-12-31.  Everything from
2019-01-01 onward is genuine **out-of-sample** prediction — the model has never
seen those observations during training.  This gives real exposure to:

- COVID crash and recovery (Feb–Dec 2020)
- 2022 inflation / Fed rate shock bear market
- 2023 banking stress (SVB, Credit Suisse)
- Any subsequent regime shifts

The dashboard keeps in-sample and out-of-sample statistics **strictly separated**.
Never rely on a blended Sharpe or a single regime duration — check whether
regime characteristics held up post-2018.

## HMM primer

A **Hidden Markov Model** assumes your observed data (here: daily feature
vectors) are generated by an underlying discrete state that you cannot observe
directly — the *hidden* state.  The model learns:

1. **Emission probabilities**: given the market is in state *S*, how are the
   feature values distributed?  (Here: a multivariate Gaussian per state.)
2. **Transition probabilities**: what is the day-over-day probability of staying
   in state *S* vs. switching to state *T*?  High diagonal values mean regimes
   are persistent.
3. **Initial state distribution**: what's the most likely regime at time zero?

Once fit, the **Viterbi algorithm** finds the single most-likely state sequence
for the entire history.  The **forward-backward algorithm** gives *posterior
probabilities* for each state at each time step — these are the three
probability bars shown in the dashboard.

HMMs are well-suited to financial markets because market regimes *are* largely
persistent (a crisis doesn't usually last one day), and the Markovian
assumption (tomorrow depends only on today's state, not the full history) is a
reasonable approximation.

## State definitions

States are **automatically labeled by realized-volatility rank** after each fit.
The state with the lowest mean 20-day annualised vol is "Calm", the middle is
"Choppy", and the highest is "Stress".  This makes labels stable across refits
regardless of how `hmmlearn` initializes its internal state numbering.

| Label   | Typical characteristics |
|---------|------------------------|
| **Calm**    | Low realized vol, positive or flat drift, tight VIX, HY spreads compressed |
| **Choppy**  | Elevated vol, mixed drift, VIX moderately elevated, credit spreads widening |
| **Stress**  | High realized vol, negative drift mean, VIX spike, flight-to-quality in TLT, HY spreads blowing out |

**These are not directional signals.**  A Calm regime can persist while markets
drift sideways for months.  A Stress regime can occur during sharp recoveries.
The model identifies *how* the market is behaving, not *where* it is going.

## Caveats

- **Lag**: Viterbi decoding is non-causal (it uses the full sequence), so the
  dashboard's state estimates benefit from hindsight.  Expect a 5–15 trading-day
  lag in detecting real-time regime transitions.
- **Descriptive, not causal**: regime labels describe statistical clustering of
  features — they do not explain *why* the market shifted.
- **Refit changes the boundary**: clicking "Refit model on full history" trains
  on all available data.  The 2019-present out-of-sample period is no longer
  genuine; treat all subsequent OOS stats as meaningless.
- **Single split**: v1 uses a single train/test split.  Walk-forward
  cross-validation across multiple windows would give more reliable performance
  estimates but is deferred to v2.

## Deployment on Streamlit Community Cloud

1. Push the repo (including `data/historical_cache.csv` and `models/hmm_fitted.pkl`)
   to GitHub.
2. Connect the repo in [share.streamlit.io](https://share.streamlit.io).
3. In the app's **Secrets** settings, add:
   ```toml
   FRED_API_KEY = "your_key_here"
   ```
4. Set the main file to `app.py`.

The app will load from the committed CSV/pkl on cold start and fetch only
incremental live data.  To refresh the cache and refit periodically, add a
GitHub Actions workflow that runs `build_cache.py` and `fit_model.py` on a
schedule and commits the outputs.
